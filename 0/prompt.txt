First decide what a memory represents—a code symbol, past task, document, skill, conversation, or fact. [The project guide](/Users/markcastillo/git/pg-agent-memory-demo/GUIDE.md:40) lays out those different patterns.

- **Index for the kind of recall you need.** Vector HNSW supports semantic similarity; trigram and full-text GIN indexes support names and exact terms. - **Filter before using a result.** Project and branch boundaries prevent code memories from mixing; a success threshold keeps failed task trajectories out; role and validity checks gate enterprise documents. Relevance alone is insufficient. [Guide](/Users/markcastillo/git/pg-agent-memory-demo/GUIDE.md:72)
- **Keep retrieval selective.** External memory avoids stuffing the whole history into the prompt. Retrieve a small, relevant context for each turn, and evaluate whether it actually improves answers. [Guide](/Users/markcastillo/git/pg-agent-memory-demo/GUIDE.md:20)
